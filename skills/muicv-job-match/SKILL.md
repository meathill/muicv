# muicv-job-match

素材库 × Mui简历岗位库，一轮自动跑完出榜单。

**边界（很重要）**：
- **只用素材已有事实**评匹配度，绝不编造、不推断。
- **榜单只在对话里输出，不落盘**。用户挑中某个岗位 → 走 `muicv-jobs` 的 `fetch` 落盘成 target；之后的单岗位深度分析走 `match` 子任务，生成简历走 `muicv-generate`。

---

## 流程（一轮自动跑完）

### 1. 读素材库

- Read 关键文件：`profile.md`（方向 / 城市）、`skills.md`、`experience/`、`projects/`、已有 `targets/*.md`（用户已经盯上的方向）。
- 提炼：目标方向（1~3 个）、核心技能关键词（8~15 个）、所在地（城市 → ISO 国家码）。
- 素材库为空或刚初始化 → 直接告诉用户先在「记录职业生涯」里补素材，这一轮跑不了；**不要 ask_question 追问**。

### 2. 检索岗位库

- 用 `search_jobs` 工具（公开接口无需 key；带 `MUICV_API_KEY` 限流额度更高）。
- 组 **2~4 组**查询：方向词 + 核心技能词组合（如「资深前端 React 远程」「full-stack TypeScript」）。本轮是广撒网，不是穷举。
- 过滤参数：
  - `workplace`：用户明确给了条件（如「只要远程」）就传；否则优先 `remote` 并在结果里注明。
  - `country`：素材库有所在地就传（ISO alpha-2）；没有就不传并说明「未限定所在地，结果里可能有仅限某国的远程岗」。
  - `utcOffset`：首轮指令里给了用户时区就传；没给就不传。
  - `kind`：默认不限；用户说「只要采集岗 / 只要社区岗」再传。
- 每组取前 10 条，按 url 去重汇总。

### 3. 逐个评匹配度（纯本地分析）

对每个候选岗位，对照素材事实评估：

- **覆盖**：岗位核心要求在素材里有对应事实 → 匹配理由必须引用素材文件（如「experience/acme-2023.md：主导 X 系统」）。
- **差距**：岗位要求但素材里找不到 → 关键产出，如实列出。
- **硬伤**：地区限制 / 时区要求 / 语言要求明显不满足 → 标「不建议」，一句话说明，不进正式榜单。

### 4. 输出榜单（对话内）

按匹配度排序：

```markdown
🟢 高匹配 — <岗位名> · <公司> · <地点 / remote>
   理由：<引用素材事实的一句话>
   差距：<没有的关键要求，没有就写「无明显差距」>
   链接：<url>
```

- 最多列 10 个。
- 末尾附「本轮检索条件」（各组 query、过滤参数、命中 mode），让用户知道怎么调整。
- 🟢/🟡 不足 3 个时如实说「岗位库里暂时没有很匹配的」，并给 1~2 条调整建议（换方向 / 放宽地域 / 过几天再扫——岗位库每日更新）。

### 5. 下一步

榜单末尾固定给一句引导：

- 「抓第 N 个」→ `muicv-jobs` fetch 落盘 + 单岗位 match 深度分析
- 「针对第 N 个生成简历」→ `muicv-generate`
- 「只看远程 / 换个方向 / 只要采集岗」→ 回到第 2 步重新检索

---

## 禁止

- 不要把榜单写成文件——用户没挑中之前，素材库不新增任何目录。
- 不要为了凑数把不匹配的岗位标成绿色。
- 不要中途 ask_question 问筛选条件——首轮指令没给的条件按默认跑，跑完在榜单里说明，用户会自己提调整。
